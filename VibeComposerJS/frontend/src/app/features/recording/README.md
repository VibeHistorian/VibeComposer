# Live recording

Choose a device with Settings → MIDI → Find MIDI inputs. MIDI access is requested only on discovery, without SysEx. Device selection is session-only; keyboard note input, count-in and the recording tick are saved UI preferences. Unsupported browsers and permission errors leave keyboard recording available.

Record live in the phrase inspector, duration popup or pattern popup starts a project-BPM loop. Optional Count-in waits one audible loop of the active phrase/section length before capturing input, independently of the ongoing recording tick. Stopping during count-in leaves no recording gesture. The phrase loop uses the phrase length; rhythm loops use four beats. In Settings → Shortcuts → General, Tap recording rhythm assigns the tap/hold key (backtick by default). Phrase recording uses physical key positions in row order: 1–0, Q–P, A–L, Z–M. Match scale/key defaults on and maps successive keys to the same scale degrees used by phrase scale/key snapping, using MIDI C2 as the base and preserving the project key and signed octave transposition. Turn it off for C-major white keys beginning at C2. The piano-roll gutter displays the current mapping, using lowercase for normal letters and uppercase for Shift variants, whenever the phrase editor is open. Normal labels take precedence when both reach the same pitch; hidden shifted aliases remain valid input. Labels share a fixed gutter column at comfortable zoom levels and alternate between two stable columns in dense views; label sizes fit the available vertical spacing. Shift raises the pitch one semitone. Text fields and shortcut capture retain native keyboard input.

Onsets snap down to the current time cell; release snaps to the closest boundary, with at least one cell. Held notes split at loop boundaries. Patterns add hits while held. Duration recording writes sounded intervals while held and pauses during silence, independently of the manual note/pause drawing tool. Unvisited time retains its prior material until the cursor reaches it. Keyboard scale matching has its own preference, independent of drawing snap-to-scale; MIDI input remains chromatic, and drum keyboards retain their unpitched mapping. MIDI velocity is retained; keyboard velocity is 90. Phrase input sounds through the selected instrument or MIDI output while held, with each sounding piano key highlighted until its final input source releases. With recording off, keyboard and MIDI input only audition, highlight keys and expand the pitch view; no provisional notes, phrase edits or history entries are created. Provisional notes grow continuously in the score, then become quantized draft notes on release. Live highlighting follows all held notes and clears during silence. Recording outside the current pitch view expands it to include the new pitches and the previously visible slice.

Stop commits a pattern recording as one project gesture. Duration recording stays in the popup draft until Validate and Save; phrases stay in their draft until Apply or Local Apply. Blur, page exit, port changes and disconnects release held inputs. Starting another recorder stops the previous one. Input ownership returns to the underlying phrase editor when a popup closes, and unrelated dialogs leave their keyboard input untouched. Metronome scheduling uses Web Audio lookahead outside Angular rendering; the first beat of each loop is accented. Tick boundaries and the beat counter follow the active loop length, including fractional sections.

Checks: `node --test scripts/live-recording.test.cjs` and, after `pnpm run build`, `node --test scripts/live-recording-browser.test.cjs`. Both are included in their normal aggregates. The browser suite simulates Web MIDI; physical device testing remains manual.
